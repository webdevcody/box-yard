Project identities: implementation design

Task task_92daa8e5177d · 27 Oct 2026 · builds on the research report (option A: identities inside one Box Yard). This is the plan the PRs follow.

In one paragraph. An identity answers "who is acting?": a GitHub login with one or more tokens, the owners it serves, a git author, an optional signing key, an optional Claude credential, the runners it may use and how much the Coordinator may see. Each project has exactly one. Every credential a turn, a clone, a push, a PR check or a Captain uses comes from one resolver, turnCredentials(), and every runner injects its result the same way, through task.json. Existing projects move to a Default identity that is today's global credentials, so nothing changes until Cody assigns another one. Secrets are AES-256-GCM encrypted at rest, never returned by the API or MCP, never seen by the model (detection and import work by reference), and redacted from transcripts.

2. Resolution order

One function, turnCredentials(project, task, boxId) in server/identity/, used by taskJson(), mirrorSpec() (clone, fetch, restore, turn-end push, WIP cleanup), the PR tracker, and the Captain's env. Nothing else reads a credential.

WhatOrder (first one set wins)
GitHub tokentask env › project env › identity token for the repo's owner › identity token for all owners › Default only: Settings › Credentials / env var / gh auth token (today's chain)
Claude credentialtask env › project env › identity's own (API key or long-lived token) › global. Exactly one Claude variable reaches the turn; the others are unset (fixes F2: a project's key used to lose to the global token).
Git authortask/project env GIT_AUTHOR_* › identity author › GIT_USER_NAME/EMAIL. Set as GIT_AUTHOR_* and GIT_COMMITTER_* env, so no stray config can change it.
Signingidentity's signing config only (none for Default unless Cody adds one)
Boxa box hosts one identity key: identityId, or identityId+env:<hash> when the project's env overrides a token, so a project with its own token never shares a box with others either

3. Injection per runner

One interface for every runner (agreed with the Docker runner task, task_c1617edfb468): the server writes the resolved credentials into task.json each turn; the runner (box-runner.mjs) applies them. Providers only say where secrets may live.

An identity whose key can only sign through an agent lists only the runners that can: Upstash and RunPod refuse it with "this identity signs through 1Password on this computer, so it can't run on Upstash boxes".

4. Signing and requireSigned

  • Per repo, each turn: gpg.format=ssh (or openpgp), user.signingkey=<secretsDir>/<task>.sign (or key::ssh-ed25519 … for an agent), commit.gpgsign=true, tag.gpgsign=true, and gpg.ssh.program for agents.
  • The runner writes the key 0600, strips it from task.json at once, and deletes it when the turn ends (and the server removes it again after the turn, in case the runner died).
  • requireSigned: before create_pull_request pushes, and before the turn-end branch push (gitPrepScript), Box Yard runs git log --show-signature / %G? over the commits origin lacks. Any unsigned commit stops the push with a loud error that lists them ("3 commits aren't signed: abc1234 …; re-sign with git rebase --exec 'git commit --amend --no-edit -S'"). Box Yard's own WIP snapshot ref (refs/boxyard/wip/*, never a branch) still goes up, so no work is lost.
  • Verification uses an allowed_signers file Box Yard writes for the identity, so a commit signed by some other key shows as bad, not good.

7. Secrets: storage, API, redaction

  • At rest: AES-256-GCM. The key comes from BOXYARD_SECRET_KEY, else a 0600 <data>/secret.key made on first use (kept out of the database, so a copied DB or backup holds no usable token). Settings › Credentials' saved values move to the same encryption (read old plaintext, write encrypted).
  • Write-only: REST and MCP return { set, fingerprint, login, scopes, expiresAt, source }. Replace and Remove are the only actions.
  • Redaction: every task event, Captain and Coordinator reply and notice passes redact() with every identity's and every global secret (cached, refreshed on change), plus the shape patterns that already exist (ghp_, github_pat_, sk-ant-, …) and private-key blocks.

8. Migration

  • One appended migration: the two tables, the Default identity (idn_default, empty: it is the global credentials), projects.identity_id = 'idn_default' for every project. Boxes without a key count as Default.
  • Projects whose env has GITHUB_TOKEN or a Claude key keep them and keep winning (now for git too, which is the F1 fix: their pushes now really use that token). The first PR's notice lists any such project so Cody can test it.
  • Rollback-safe: columns are additive; the global credentials row stays readable.

9. UI

  • Settings › Identities (new section after Credentials): cards per identity (login, owners, author, signing fingerprint, Claude kind, runners, projects, last test), Add, Edit, Test, and "Import from this computer" (runs detection, shows proposals with evidence, imports on click). All edits are a draft until Save; tokens are write-only fields.

  • Badge: a small colour dot + name in the sidebar project row, project settings and the task ⋯ details. Not in the project header (#83). Container queries for narrow panels.
